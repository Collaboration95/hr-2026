Decision layer: algorithm, schema and benchmarks

1 · Framing

What went in

EUDR screening intersects farm plots with years of forest maps and repeats the check when a map updates. The decision layer keeps only the facts that check reads.

Problem
Compact multi-layer, multi-year storage and fast queries that keep what is needed to reproduce plot-level compliance decisions.
Layers
Hansen GFC 2025 v1.13 treecover2000, lossyear, datamask (about 28 m cells) and JRC Global Forest Cover 2020 v4 (about 9 m cells).
Region
Surat Thani, Thailand: 98.772–99.081°E, 8.431–8.582°N. 1,233 × 604 = 744,732 cells, about 34 × 17 km. 17 supplied plots (not shown on this page).
Stack
Python 3.14 engine (numpy, rasterio, shapely) and a React + TypeScript + Vite app. This page is static HTML, JavaScript and three.js, no build step.
AI use
No machine-learning model in the pipeline. Performance work ran as verification loops: AI agents proposed each speed-up, and a change was kept only if the benchmark improved and the every-cell proof still matched. A separate validator agent, tasked only with breaking results, re-derived them with its own code. A learned codec selector was tried and dropped because it lost to a plain GeoTIFF.

3 · Schema

20 codes, two levels

The screening level keeps every post-2020 loss year. The decision level forgets the loss year on land that was not forest in 2020, so codes 3–7 merge into code 2.

4 · Store file

.plds byte layout

One file holds a 20-byte prefix, a canonical-JSON header and the payload: four bit-planes plus sparse loss events coded as rank gaps. The split encoding is 28% smaller than the best GeoTIFF of the same codes. Every check runs before a decoded cell is used.

    10 · Limits

    Design limitations

    1All-or-nothing edge cells

    A cell counts fully when its centre is covered. Answers are counts of about 0.076 ha cells; partial edge coverage and the EUDR 0.5 ha minimum area are not modelled.

    2JRC sampled once per Hansen cell

    The centre of its 3×3 block. Centre, 3×3 majority and any-forest give the same decision for all 17 plots, but only one plot has mapped forest.

    3The layer is rule-specific

    A changed rule or an added layer, such as protected areas, means re-deriving from the lossless audit tier: seconds per region, and about 7 CPU-minutes per tile (estimated from 6 of 160 strips).

    4The largest speed-ups need registration

    44×–410× apply to plots registered in advance. An unseen boundary gets 5.2×.

    5Scale evidence is split

    Storage was measured on a whole 10° tile; query timing on one region.
