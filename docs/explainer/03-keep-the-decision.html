01 / Start with the contract

Which facts can change an answer?

Think of packing a bag for a particular job. Keep the tools that the job uses. First write the job down: a query contract is the exact set of questions, inputs and answer rules the program promises to follow. EUDR means the EU Deforestation Regulation; this prototype implements a documented map screening rule, not a legal verdict.

Hansen supplies annual tree-cover loss and a land/water map. JRC, the European Commission’s Joint Research Centre, supplies the mapped forest class for 2020. An attribute is one fact stored for a cell. Select a question to see its attributes.

72%

Canopy values nobody reads

Hansen’s treecover2000 is the percentage of canopy in 2000. It uses 414,142 of 576,999 Hansen file bytes. None of these questions reads its values.

Earlier loss is outside the window

Loss dated 2001–2020 is before the post-cut-off period. JRC supplies the 2020 baseline. An earlier Hansen loss does not erase a JRC 2020 forest cell.

Only one JRC cell is read

The grids nest exactly 3:1 on each axis. Each Hansen cell contains a 3×3 JRC block. Our rule reads the centre, so the other eight cells’ values are unused.

Unused values and missing-data masks are different. The canopy percentages are dropped, but their validity mask—a per-cell “data available” flag—still contributes to “known”, as it did in v1. Unknown stays unknown.

The Hansen cell is 0.00025° wide: 0.9 arc-seconds, often rounded to “1 arc-second”, about 28 m here. JRC’s finer detail is about 9 m. Discarding that detail is safe for the chosen centre rule; it does not prove that this is the best environmental sampling rule. See resolution.

02 / A small alphabet

One byte, the facts the rule needs

A luggage tag replaces a long description with a short code. Here, uint8 means an unsigned integer stored in one byte: it can hold 0–255. We use just 20 values, 0–19. A code combines land status, forest state and any post-2020 loss year.

Interactive / synthetic single cell
10

code = 2 + 6 × forest_state + post_index

For land: state 0 = non-forest, 1 = forest, 2 = unknown. Index 0 = no loss after 2020; indices 1–5 = 2021–2025. Code 0 means unknown support; code 1 means water.

Screen vs decision. A level is a named contract. eudr-screen.v1 keeps post-2020 loss on all land and answers Q1–Q3. eudr-decision.v1 answers Q1–Q2. It maps non-forest loss codes 3–7 to code 2, forgetting their year.

Loss on unknown forest state is retained. It can prevent a confident “no” answer. This is why unknown is a separate state, not an alias for non-forest. See yes / no / unknown.

03 / What each level forgets

Pick the notebook for the job

Think of progressively smaller notebooks: full observations, screening facts, decision facts, then answers for named plots. Each step gives up the ability to answer some new question. Select a rung.

These are full-file bytes for the region. L0 is the retained Hansen-only audit store; JRC is separate. L4 is the current uncompressed JSON table with both levels. It is a sidecar, not a raster and not smaller than L2 here. The registered cell index adds 4,096 B separately. The rung names follow the experiment; this is not a claim that each rung is smaller.

04 / Separate the regular from the rare

Four sheets and a short event list

A bit-plane is a sheet of yes/no answers, one bit per cell. Instead of repeating “land, forest, no loss” in every cell, the split encoding separates common states into sheets and records rare loss events in a short list.

Stepper / invented 8 × 8 grid · not company data
Numbers = stored values▨ = unknown



Sparse means most cells have no event. The encoder stores event positions as gaps. A varint, or variable-length integer, uses fewer bytes for small numbers. It stores those gaps, plus one year symbol per loss event. The implementation may choose a loss-event bit-plane instead if that is smaller, or gaps among forest/unknown-forest cells.
The encoder reorders the grid into eight-column strips to keep related bits together. It tries compressed streams using LZMA2 and zstd, two lossless compressors, plus raw streams, then keeps the smallest. This changes the byte packing, not the code values. No learned model chooses the retained encoding.
A file you can recognise and check
PLDECID1 is the eight-byte magic marker at the front of the file. “Magic” means a fixed signature identifying the format. The marker stays PLDECID1 although the current format version is 2.
1 / Prefix · 20 Bmagic: 8 Bversion: 4 Bheader length: 4 Bheader CRC32: 4 B
2 / JSON header · 675 BLevel, shape, grid, encoding and hashes.Canonical JSON
3 / Payload · 5,451 BEncoded planes, event positions and years.Total: 6,146 B
Byte counts above are for the retained decision store, not the toy grid. The three 4-byte integers are little-endian: the least significant byte comes first.
Canonical JSON is a deterministic text representation: sorted keys, fixed separators and no ambiguous number spellings. A header describes the file; the payload carries its encoded data. CRC32 is a checksum that detects accidental changes to the header. SHA-256 hashes check the payload and decoded raster. These checks establish integrity, not authorship.

05 / Show the standard control
The main win is choosing the facts
A smaller alphabet is easier to compress. The fair control is a standard GeoTIFF containing the same decision codes, not only the original multi-layer files. A GeoTIFF is the standard georeferenced raster file already introduced.

Most of the gain comes from layer analysis. The independent validator attributes about 96% of the reduction to dropping unused attributes in its broader control study. That study includes a composite of standard formats. It is a different comparison from the single GeoTIFF shown above; do not calculate “96%” from these five rows.
The custom split store is 28% smaller than the 8,532 B GeoTIFF control. Against only the files the decision reads—lossyear, datamask and JRC, totalling 209,095 B—it is 97.1% smaller. These denominators answer different questions; both are useful.
