01 / The argument

Equal cells give equal bags of codes

Think of counting coloured counters in a bag. The order does not matter; the number of each kind does. A multiset is that bag: values may repeat, and their counts matter. After the centre rule selects cells, every output depends only on their code counts and the number of selected centres outside the stored region.

Interactive proof sketch / invented 4 × 4 grid

Click or focus a cell and press Space to select it. Both paths use that same selection. Toggle the deliberate error to see why equality at every cell matters.

  1. A polygon picks the same cell centres on the same grid under the same inclusion rule.
  2. If every position has the same code in both representations, the selected multisets are equal.
  3. The out-of-chip count is also the same. The deterministic reducer gets identical inputs, so every output field is identical.
This is why an exhaustive cell comparison supports every permitted polygon under that rule, rather than just the 17 examples. The argument assumes the same level, grid, selection and reducer semantics. It says nothing about whether the source maps are environmentally correct or the screening rule is legally sufficient.

03 / Try to break the claim
Generated shapes, plus deliberate mistakes
Fuzzing generates many varied inputs to find cases an author might not think to write by hand. The seeded generator builds synthetic polygons with holes, separate pieces, water, chip edges and edges passing through cell centres. A fixed seed makes a run repeatable.

9,829 / 9,829 valid polygons gave equal answers. The remaining 171 were invalid and rejected identically. Rejection is an expected result, not a missing comparison.

04 / Independent validation
Different arithmetic. A separately written reducer.
A second examiner should not mark an answer using the first examiner’s workings. The validator in validation/decision/ reads the original layers and uses its own reducer, written from the contract prose. Its reference side never imports engine.decision.
Exact rational arithmetic represents numbers as fractions, rather than rounding each intermediate operation to a floating-point number. The validator uses Python’s Fraction for JRC lookup and point-in-polygon tests. It can therefore challenge both the integer and floating-point implementations.
216,360
Adversarial selection geometries
Zero mismatches. Cases include tiny needles, vertices a tiny representable step apart, very small cells and a nearly 100,000-vertex circle.
17
Validation scripts passing
After fixes, scripts were updated for the new formats and rerun. They keep the original verdict checks. The optional heavy run adds the large-polygon case.
Adversarial means chosen to expose weaknesses, especially boundary and numeric cases, rather than represent an average farm. The validator also tests injected unknowns, possible-world interpretations of yes/no/unknown, store byte accounting, source independence, corruption and cost-model assumptions.
The region-wide equality argument and selector testing cover different risks. The theorem assumes shared selection. The independent selection work checks that the fast method follows the original boundary-inclusive rule within the supported input domain. Finite tests are not a formal proof over all floating-point polygons.

05 / The failures are evidence too
The checks became stronger after review
Hardening means making malformed, stale or corrupted input fail safely. The independent review found real faults. Each was fixed with a regression test that fails on the old implementation. Open a finding to see the failure and repair.
01 / Header CRC32
The descriptive JSON header was not protected. A corrupted grid or level could change an answer even when the payload hash passed. Format v2 adds a CRC32 checked before parsing; typed fields and the header length are validated.
Where this lives · engine/decision_store.py → _file_bytes() · read_store()
02 / OverflowError
Huge numeric input could escape as an OverflowError instead of the promised ValueError. Header scalar checks reject non-finite or unrepresentable values and normalise malformed-input failures.
Where this lives · engine/decision_store.py → _finite() · _parse_header()
03 / Varint amplification
A tiny hostile event stream could request a large allocation. Event counts, stream lengths and allocation bounds are checked before arrays are expanded. Varints must use the canonical, bounded representation.
Where this lives · engine/decision_store.py → _varint_limit() · _unvarints() · _decode_split()
04 / Level binding
Reading decision codes as screen codes silently invented a zero Hansen-only loss result. Store-aware evaluators derive the level from the header and refuse a conflicting requested level. Raw raster callers must still pass the correct level.
Where this lives · engine/decision.py → bind_level() · evaluate_store()
05 / Registry and table content binding
PLDREG2 checks its header and payload hashes and requires the current grid. The table checks content_sha256 on load. Lookup also binds geometry and per-level store hashes. A table keyed by raw raster bytes needs the live grid.
Where this lives · engine/decision_index.py → _parse_registry() · registry_lookup() · load_table() · table_lookup()
06 / Aggregate registry cap
A bound on each plot was not enough: many individually legal runs could expand into excessive total memory. MAX_REGISTRY_CELLS caps the sum across plots before expansion, closing the residual parser finding.
Where this lives · engine/decision_index.py → MAX_REGISTRY_CELLS · _parse_registry()
07 / Proof gate
A proof with a missing store must not appear complete. The default all_pass gate now fails if a store is absent or unreadable, and the command exits 1. A deliberately named opt-out remains available for limited experiments.
Where this lives · engine/decision_proof.py → build_proof() · main()
08 / Cost model
The earlier model confused a sum of read time over eight workers with single-process elapsed time and used a registry placeholder. It now reads measured benchmark inputs and single-process tile timing. Prices, land fractions and a not-yet-built strip container remain explicit assumptions.
Where this lives · engine/decision_scale.py → benchmark_inputs() · read_timing() · cost_model()
Integrity is not authenticity
A seal can tell you that a package changed, without telling you who packed it. Integrity checks whether bytes match an expected checksum or hash. Authenticity establishes that the expected bytes came from a trusted source.
CRC32 and self-stored SHA-256 hashes detect accidental corruption. An attacker who can edit a file can recompute its hashes. A caller that needs authenticity must pin a genuine expected file hash through a trusted channel, such as read_store(expected_sha256=...). The table is keyed by the expected store-file hash, but its own content hash is not externally pinned in this prototype.
Passing the checks does not authenticate a deliberately rehashed table or registry. Nor does it prove that a map observation is environmental truth. Those are separate trust questions.

06 / Keep the boundary of the claim
Exact representation, bounded conclusions
“Same answers” has a defined boundary. Use the claim with its rule and scope attached.
One region, one laptop
Query timings cover a 34 × 17 km region, the 17 supplied plots and synthetic shapes on one laptop with a warm file cache. Whole-tile results measure storage, not query speed.
JRC at the centre
Each Hansen cell reads one of nine JRC cells. Centre, majority and “any forest” gave the same plot flags here, but only one supplied plot had mapped 2020 forest. That is a weak sensitivity test.
Some EUDR tests are absent
The prototype does not apply the 0.5 ha minimum area or the “able to reach 5 m in situ” test. Counts are cells, not hectares. It does not establish legal production.
No protected-area layer
WDPA, the World Database on Protected Areas, is not included because its licence is unresolved. Absence from this prototype is not evidence of no protected-area overlap.
Registered shortcuts only
The registry and table serve plots registered in advance. A new or changed boundary requires selection. A changed layer invalidates a saved table answer.
A versioned question
Codes retain loss years only through 2025. A rule, horizon or sampling change requires re-deriving from the pinned originals. The lossless audit tier and source provenance remain available.
Say in the pitch: “These are identical plot-query outputs under our documented rule. Mapped loss on mapped 2020 forest is an observation for review, not a compliance verdict.”

07 / From a prepared checkout
Run the same pipeline in order
Run these in order from the repository root, after the setup in README → Running the local lab. A fresh clone needs the private sample-data bundle; it is not in git. The 17 boundaries and due-diligence CSV must be provided locally through the authorised handover. The commands cannot reproduce those checks from tracked files alone.
The full scale step also needs the raw public whole-tile cache. Store/proof commands write derived artifacts; these buttons only copy text and do not execute anything.
1. Build the stores and standard-format controls (about 20 s).
.venv-data/bin/python -B -m engine.decision_store
2. Exhaustive comparison, 17-plot checks and fuzzing (about 15 s).
.venv-data/bin/python -B -m engine.decision_proof
3. Build the registered cell index and answer table.
.venv-data/bin/python -B -m engine.decision_index
4. Run the isolated benchmark (about 2.5 min).
.venv-data/bin/python -B -m engine.decision_benchmark
5. Rebuild layer analysis, whole-tile storage and cost estimates. Requires the raw public tiles.
.venv-data/bin/python -B -m engine.decision_scale
6. Build the app summary.
.venv-data/bin/python -B -m engine.decision_export
7. Run the independent validator.
.venv-data/bin/python -B validation/decision/run_all.py
Inspect the generated artifacts/decision/ files and the validator’s out/ reports. A failed proof gate or mismatched answer digest stops a result from being published. Check exit status; a readable report alone does not mean the checks passed.
