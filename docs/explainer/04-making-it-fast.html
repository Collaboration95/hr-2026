01 / Split the work

Finding cells dominates the old hot path

Imagine a library visit. Finding the books and reading them are different jobs. A plot query also has two jobs: selection finds the cells whose centres lie in the boundary; reduction turns their values into counts and flags. “Hot” means the data and code are already loaded.

Plan-time profile / one warmed batch of 17 plots

Total ≈1.6 ms. This is the early plan-time profile, before the isolated benchmark. The canonical benchmark below measures the retained v1 path at 1.44 ms. Do not combine the two runs as if they were one measurement.

In v1 the reducer reads three Hansen bands—one array per attribute—and constructs a histogram, a count of cells in each value category. Canopy percentages need 101 bins, one for each value from 0 to 100. Compressing files cannot make this hot selection work disappear. See why v1 had no hot-query gain.

02 / Change the representation

One band. Twenty counters.

Replace three books with one concise index card. The decision representation stores a single uint8 band, an array of one-byte codes. The reducer counts just 20 possible values. Forest classes and post-2020 years are already combined, so it does not repeat the cross-layer lookup for each query.

03 / New boundaries

Cross the fence, keep the edge cases exact

Scan a fence line from left to right. Each time you cross it, you switch between outside and inside. A scanline applies that idea to a horizontal row of cell centres. It computes where the row crosses the polygon’s edges, then takes the clearly interior centres together.

Interactive schematic / synthetic polygon only

The precise version uses an even/odd crossing count over all rings. A ring is a closed outline; interior rings describe holes. Holes and separate polygon pieces follow the same rule. Centres near a crossing, on a vertex or on a horizontal edge go to shapely.covers. Shapely is the Python geometry library; its GEOS engine performs the exact same boundary-inclusive predicate used in the old selector.

This is a hybrid: fast bulk decisions plus the original test for ambiguous cases. It preserves the centre inclusion rule. It does not move the polygon or round centres to a coarser grid. Inputs outside the tested numeric range fall back to the original selector.

5.3×

The 17 plots’ shapes

0.27 ms for the decision fast path vs 1.44 ms for retained v1. The selector change alone is 4.3× vs the 1.17 ms decision path. Small windows are scanned in plain Python and the histogram is built straight from runs of selected centres, so this is the selector plus a fused reduction.

1.9×

Less faster on boundary-heavy shapes

25.0 µs per polygon vs 47.9 µs with ordinary selection (it was 1.88× after Phase 2, 1.16× after Phase 1 and slower, 0.81×, at the start). Many centres still need the exact fallback, so the gain is smaller. A batch evaluator that answers many polygons in one pass takes 8.1 µs here, but only helps when a batch is in hand.

04 / Repeated boundaries

Find the cells once, read their new values

A library bookmark remembers where to look next time. The registered-plot index remembers which cells a known boundary selected. A plot is registered once and re-checked when the maps update. That repeated workload makes selection worth doing once.

Synthetic cell positions / one row-major grid

Give every cell an index: row × grid_width + column. Consecutive indices become runs, each stored as a start and length.

Selected indices: [12, 13, 14, 22, 23, 24, 25, 32, 33]

Nine selected cell positions. These invented numbers describe no supplied plot.

The PLDREG2 registry file binds the index to the geometry hash and the grid’s shape, coordinate system and affine transform. A hash is a deterministic fingerprint of bytes. SHA-256 is the hashing algorithm used here. Change the geometry or grid and the lookup misses. Change only layer values on the same grid and the selected cells can be reused, while the reducer reads the new codes.

Hot re-checks take 0.033 ms for 17 plots: 44× faster than retained v1. A numpy-free version of the same re-check takes 0.022 ms (65×). Selection is skipped; reduction still runs. The registry sidecar is 4,096 B, so the 6,146 B decision store plus index totals 10,242 B. This path serves registered plots only.

05 / Unchanged inputs

A saved answer with a precise key

A materialised view is a database result calculated in advance and saved. The answer table takes the same idea one step further: store the full answer for each registered plot. No selection or histogram is needed on a hit.

Synthetic cache invalidation / no supplied boundaries

The request key

SHA-256 prefixes are from invented geometry and layer text. The real key compares the full hashes and contract level.

The key is plot_id + geometry SHA-256 + store-file SHA-256, at a stated level. A changed boundary, layer file or level cannot use the old answer. table_lookup returns a miss; the caller must evaluate the current inputs and refresh the table. The demo models that workflow. The lookup function does not recompute by itself.

Hot lookup takes 0.0035 ms for 17 plots: about 417× faster than retained v1, with geometry hashes supplied from registration. This is a cached answer. If the service hashes the submitted geometry on every call, lookup rises from 0.20 to 3.68 µs per plot. Verifying the layer file’s hash also has a cost, paid once per process in this model.

The table file stores both levels and is 20,650 B. load_table verifies its own content hash. For a table keyed by raw raster bytes rather than a store file, the live grid is also required. A self-hash does not authenticate a file; see integrity and authenticity.

06 / Count the door-opening time

A faster query can still wait for Python

Opening the library door can take longer than reading the index card. A fresh process starts a new Python interpreter. It has to import its libraries and load the data before answering. End-to-end timing includes that start-up; “fresh-process load + query” below begins after imports and geometry reading.

Original layers

Import NumPy for arrays, Shapely for geometry, and rasterio/GDAL for geospatial files.

Decision + registry

No rasterio or GDAL, the geospatial file-reading stack. Registered queries also avoid Shapely.

50 ms end-to-end
37 MB peak memory

Answer table

Only the stdlib: Python’s built-in standard library. No arrays or geospatial libraries.

21 ms end-to-end
21 MB peak memory

Bare interpreter start-up is about 15 ms on this laptop. The table path approaches that floor. The remaining time is mostly process start-up and imports, not lookup work: importing NumPy alone is about 25 ms of the roughly 50 ms index run, so Phase 1 on 15 October, which cut hot and load times, left end-to-end almost unchanged. Phase 2 added a numpy-free version of the registered re-check, built on the standard library only. It never imports NumPy, so a fresh process answers in about 25 ms instead of 50 (4.6× against retained v1); what is left is interpreter start-up plus the benchmark’s own floor. Phase 3, a small one, sped up the shared histogram reducer and removed a 2 ms first-call import from the batch evaluator; it moved hot times, not these end-to-end ones. The decision paths never import rasterio/GDAL.

08 / The engineering lesson

The data and the workload reveal different levers

The first build defined fidelity as keeping every pixel value. That made compression the main available lever. Entropy is a measure of how much unpredictable information a signal contains. No lossless compressor can promise to shrink arbitrary noisy bands beyond the information they carry. And after decompression, the same hot selection and reduction work remains.

Ask what the answer reads

The representation changes what is stored. That is safe only with a proof that every permitted polygon still gets the same outputs. A handful of matching plots is not enough.

Ask what users repeat

Indexes and materialised views come from the workload: registered plots are checked again when layers update. Looking only at the raster hides this opportunity.

Before the hot path was decomposed, selection’s share was invisible. A faster reducer alone left most work in place. The profile identified the next bottleneck; the workload revealed when to skip it.

Exactness also shaped the algorithm. A simple scanline approximation might be fast, but a boundary passing through a centre cannot be guessed. The hybrid keeps bulk speed and delegates numerically ambiguous cases to the original predicate. Its boundary-heavy slowdown is part of the result.

Say in the pitch: “New boundaries use exact fast selection. Registered plots reuse their selected cells. Unchanged geometry and layers can reuse the whole answer. We measure those separately.”
