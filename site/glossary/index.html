Geospatial basics · 22 terms

Geospatial basics

What a raster, a cell and a coordinate system are, before any forest comes into it.

Affine transform

A fixed rule that turns a cell's address (column, row) into a map coordinate, like a ruler pinned at a known corner. Plotline accepts north-up grids with no rotation.

See The data

Band

One attribute stored on a grid, like one sheet in a stack of graph paper. Hansen has three bands: tree cover in 2000, loss year, and a land/water mask.

See The data

Cell / pixel

One square of a raster. It holds one value describing a patch of ground, about 28 m wide for Hansen. A count of cells is not an area in hectares.

See The data Start: the data

Chip

A rectangular cut-out of a bigger raster. Our Hansen chip is 1,233 × 604 cells (744,732) and covers all 17 plots; the JRC chip is 3,695 × 1,809 cells. A chip is a window you choose; a tile is a piece the data publisher chose.

See The data

Coordinate reference system (CRS)

The convention that gives coordinates a meaning on Earth, like saying which address system a street number belongs to. Both layers here use EPSG:4326.

See The data

EPSG:4326 / WGS84

The standard longitude and latitude system used by GPS. EPSG:4326 is its catalogue code. Plotline requires it, with a north-up grid, and puts longitude first.

See The data

GeoJSON

A text format for geographic shapes. The company's 17 plot boundaries came as GeoJSON, with positions written [longitude, latitude] and any extra rings treated as holes.

See The data

GeoTIFF

An image file that also records where on Earth it sits: its grid size, value type, coordinate system and transform. Hansen and JRC both come as GeoTIFFs.

See The data

Grid

The regular pattern of equal squares that a raster is made of. Hansen's grid and JRC's grid differ, but each Hansen cell holds an exact 3 × 3 block of JRC cells.

See The data Start: nesting

Hectare (ha)

10,000 square metres. The 17 plots are smallholdings of 0.53 to 20.07 ha. Our counts are cells, not hectares.

See The data Findings

Hole

An interior ring cut out of a polygon, like a pond in a field. A cell centre strictly inside a hole is not counted; one exactly on the hole's edge is.

See How Plotline works

Latitude / longitude

Angles that locate a point on Earth: latitude north or south, longitude east or west. A degree is not a fixed distance on the ground.

See The data

Mask (validity mask)

A yes/no marker saying whether a value is usable, like a checkbox beside a form field. A cell whose mask says unusable stays unknown, even if its stored number is zero.

See The data

MultiPolygon

One shape made of several separate polygons, like a farm with two disconnected fields. A cell centre covered by more than one part is counted once.

See How Plotline works

Nodata

No usable observation in a cell, like a blank form field. It is different from a real zero such as 'no loss'.

See The data

Overview

A low-resolution copy of a raster stored inside the file, like a thumbnail. Plotline's queries read the full-detail values, never an overview.

See The data

Polygon

A closed outline around an area, like string around pegs. It has an outer ring and optional holes. Every supplier plot is a polygon.

See The data

Raster

A map stored as a grid of squares, one number per square, like graph paper. Satellite maps are rasters. Its colours are only a way of drawing the numbers.

See The data Start: the data

Resolution

How big one cell is on the ground. Hansen is about 28 m (0.00025 degrees); JRC is about 9 m (1/12000 degree). Finer does not by itself mean a more correct legal answer.

See The data

Tile

A piece of the world's coverage: Hansen and JRC publish 10° × 10° source tiles (ours are Hansen 10N_090E and JRC N10_E90). Inside a TIFF file, 'tile' can also mean a storage block, which is a different use of the word.

See The data

uint8

A whole number from 0 to 255 stored in one byte. Hansen's bands and Plotline's code rasters use it. Compression changes the stored bytes, not the type's range.

See How Plotline works

Vector

Geometry described by coordinates rather than a grid of cells, like a traced outline. Farm plots are vector; forest maps are raster. The query lays one over the other.

See The data

Layers and data · 12 terms

Layers and data

The public maps and the company's sample, and what each band means.

Canopy closure (tree cover %)

The share of ground covered by tree crowns seen from above. Hansen's treecover2000 stores it as a percentage from 0 to 100 for the year 2000. No EUDR question here reads it.

See The data Start: what we built

Datamask

Hansen's land-context band: 0 no data, 1 mapped land, 2 permanent water. It is cheap to keep and stops 'unknown' being mistaken for 'no loss'.

See The data

Declaration (supplier)

What a supplier says about a plot in its due-diligence record: the layer it checked, what that showed, what it did about it, and final statuses. A declaration is a claim to check, not a fact.

See Findings The data

Hansen 2023 v1.11

The older Hansen release, current in the supplier's era. We tested the declarations against it with the method fixed in advance, and the 2021 to 2023 counts were identical to v1.13.

See Findings

Hansen Global Forest Change (GFC) v1.13

The University of Maryland tree-cover loss dataset at about 28 m. Our version is the 2025 release, v1.13, with treecover2000, lossyear (2001 to 2025) and datamask. Loss is not a legal finding of deforestation.

See The data Start: the data

JRC Global Forest Cover 2020 (GFC2020) v4

The EU Joint Research Centre's map of forest or non-forest in 2020, the EUDR cut-off year, at about 9 m. We kept it as its own layer on its own grid. v3 would not download, so we used v4.

See The data Start: the data

Loss cell

A cell where Hansen records tree-cover loss in some year. 'Post-2020 loss cell' means the year is 2021 to 2025. Loss alone does not say the land was forest in 2020.

See The data Findings

lossyear

Hansen's year-of-loss band: 0 means no mapped loss, 1 to 25 mean the years 2001 to 2025. A masked value stays unknown even if its stored number is zero.

See The data

Plantation (and forest class)

JRC's forest definition excludes land predominantly in agricultural use, such as rubber and oil-palm plantations. Loss on land JRC does not class as forest therefore does not count as deforestation here; what caused it is not established by these layers.

See The data Findings

Supplied sample

The 17-row CSV and 17-polygon GeoJSON SystemEarth gave us on 12 October. It is private: this pack never shows real outlines or rows.

See The data Start: the data

treecover2000

Hansen's canopy-percentage band for the year 2000. It is about 72% of Hansen's bytes in our chip and no question in the screen reads it, so Plotline drops it.

See The data Start: what we built

WDPA (protected areas)

The World Database on Protected Areas. We did not use it because its terms of use are unclear, so Plotline does not check protected-area overlap.

See SystemEarth and the EUDR

The rule · 17 terms

The rule

What the EU regulation asks, and the written rules we apply to answer it.

Any-overlap rule

The alternative to the centre rule: count a cell if any of it touches the plot. Switching to it adds 337 cell memberships and flips five plot-period flags, which is why the rule must be written down.

See Findings How Plotline works

Centre rule (centre-inclusion rule)

A cell belongs to a plot if the plot covers the cell's centre point. It is the usual default in zonal-statistics tools, and the rule is part of the decision: change it and answers can change.

See How Plotline works Start: one plot

Compliance verdict

A legal judgement that a plot meets the regulation. Plotline does not issue one. Its results are mapped observations under a written rule.

See Findings Pitch

Contract (query rule)

The exact question and the exact outputs permitted, agreed before measuring, like a checklist before an audit. The screening contract and the smaller decision contract keep different facts.

See How Plotline works

Covers

A geometry test that counts a point inside the shape or exactly on its edge. Plotline uses it for cell centres, so a centre on the boundary or on a hole's edge counts.

See How Plotline works

Cut-off date

31 December 2020. EUDR asks whether land was forest then and whether it has been cleared since. Everything before it is baseline; only later loss on that forest matters.

See SystemEarth and the EUDR Start: the cut-off line

Deforestation-free

The status a supplier must demonstrate for each plot under EUDR: no forest cleared after the cut-off. In this pack, 'deforestation' means mapped loss on mapped 2020 forest, not a legal finding.

See SystemEarth and the EUDR

EUDR

The EU Deforestation Regulation. Companies selling products such as rubber, palm oil, cocoa or coffee into the EU must show each supplying plot is deforestation-free. Plotline screens one part of that; it is not a full legal assessment.

See SystemEarth and the EUDR Start

Forest (as the maps define it)

Per the JRC metadata: land over 0.5 ha with trees taller than 5 m and canopy over 10%, or able to reach those in place, excluding land mainly in agricultural or urban use. Check the wording against the regulation before quoting.

See The data SystemEarth and the EUDR

Indication of deforestation

The phrase in the supplier file for a check that flagged possible loss. Five plots (P-0003, P-0005, P-0008, P-0010, P-0013) record one, resolved by on-site verification. Those five show no Hansen loss in 2021 to 2023.

See Findings

Mapped loss on mapped 2020 forest

Our careful wording for what the decision layer finds: a cell JRC maps as forest in 2020 and Hansen maps as lost in 2021 to 2025. Only P-0001 has it: 2 cells in 2022. Say this, not 'deforestation found'.

See Findings Start: what it found

Minimum area (0.5 ha)

EUDR's forest definition has a size threshold of 0.5 ha. No layer in Plotline applies it, so results are about mapped cells, not legal forest.

See Findings

Production place (plot)

The piece of land where a commodity is grown. EUDR needs its boundary, which is why each supplier row has an outline. We use 'plot' throughout.

See SystemEarth and the EUDR The data

Q1, Q2, Q3

The three questions the screen asks. Q1: was it forest on 31 Dec 2020? Q2: has that forest been lost since? Q3: does Hansen alone show any loss in 2021 to 2023, the supplier's own check?

See Start: what we built How Plotline works

Question for the reviewer

How we describe any difference between a declaration and the maps: something a human should look at, not a red flag or an accusation. The supplier may have used manual review, another layer or a buffer.

See Findings Pitch

Support

How much usable information backs an answer: none, partial or complete. A 'yes' can come with partial support; a zero count does not by itself prove 'no'.

See How Plotline works

Tri-state / known zero vs unknown

Every flag is yes, no or unknown, shown in the data as true, false or null. Null must never be shown as zero or false: 'no loss' is a known zero, while 'unknown' means we could not tell.

See How Plotline works

Plotline's build · 29 terms

Plotline's build

The codes, layers, proofs and records that make up the product.

20-value code

The one small number each map cell is reduced to: unknown, water, or land × (not forest, forest, forest unknown) × (no loss since, or loss in 2021 to 2025). 2 + 3 × 6 = 20.

See Start: the 20 codes How Plotline works

Answer table

A stored answer for each registered plot, looked up by plot ID, geometry hash and store hash. It is the fastest path (about 410×) but cannot answer a boundary it has not seen.

See The speed story How Plotline works

Audit tier (lossless v1 store)

Our first store, which keeps every original value and mask. It is only 8.6% smaller and no faster once loaded, but it stays so a rule change can be re-derived and checked.

See How Plotline works

Bit-plane

One yes/no layer pulled out of the values, like keeping one checkbox from every form. Packing eight per byte stores sparse facts such as land, water and forest compactly.

See How Plotline works

Compression / codec

Storing the same information in fewer bytes. A codec is the recipe. Lossless codecs return identical values; Plotline's big saving comes first from dropping unread attributes, then from compressing what is left.

See How Plotline works

Decision fidelity

The share of plots whose outputs all match the original-layer answer. SystemEarth's slides ask for it. For us it is 17 of 17 plots, and exact for every cell.

See How Plotline works The event and the brief

Decision layer

A reduced raster holding only the facts the decision reads. Ours forgets loss years on land that was not forest in 2020, so it answers Q1 and Q2 exactly. 6,146 bytes against 623,237 for the original layers.

See Start: layers collapse How Plotline works

Exhaustive check

Comparing every member of a finite set instead of a sample, like checking every tile of a mosaic. Our proof compares all 744,732 cell codes against an independent original-layers path.

See Start: the proof How Plotline works

Fuzzing

Testing with lots of generated, awkward inputs, like trying thousands of oddly shaped keys. We fuzzed 9,829 polygons with holes, multipolygons, edges through cell centres, chip edges and water; both paths agreed on all.

See How Plotline works Start: the proof

Histogram

A count for each value or category, like labelled jars of counters. The original query uses 101 canopy bins and 26 loss-year bins; the decision reducer uses 20 bins, one per code.

See How Plotline works

Histogram reducer

The one shared routine that turns a 20-code histogram into the contract's answer (counts, flags, support). Every live-answer path uses it, so speeding it up sped them all.

See The speed story

Independent validator

A separate effort whose only job was to break the claims, using exact rational arithmetic and its own reducer. It confirmed the proof, tried 216,360 extra adversarial polygons without a mismatch, and found seven hardening issues that were fixed.

See How Plotline works

Learned codec selector

An ML experiment that chose a compression setting per patch. On a sealed held-out region it lost to one fixed setting, so it was rejected. Kept as an honest negative result.

See How Plotline works The speed story

Live query

An app view (and local read-only service) that answers a new, temporary polygon or rectangle on both the original and compact paths and returns a receipt.

See How Plotline works

Lossless / lossy

Lossless means everything can be recovered exactly; lossy means something is thrown away. The decision layer is lossy on what no question reads and exact on what the decision does read, which is why every cell is checked.

See How Plotline works

LZMA / LZMA2

A family of lossless compressors. The winning stream setting for our code planes is mostly LZMA, tuned against zstd and uncompressed bytes.

See How Plotline works

Negative control

A deliberately broken case that the test must catch, like planting a wrong answer to check the marking works. We flipped one cell, moved a vertex and flipped a JRC bit; all were detected.

See Start: break one cell

Oracle (independent path)

A separate way of computing the same answer, written without the code under test, so a shared mistake cannot hide. Ours rebuilds each cell's code from the original GeoTIFFs and has its own reducer.

See How Plotline works

Pixel fidelity

Whether the original values and masks survive encoding. For the lossless store it is 100%. For the decision layer it is 100% on every attribute the decision reads; dropped attributes are listed, not called lossless.

See How Plotline works

Plotline

The name of our product: an evidence-review workflow for supplier declarations and mapped observations, backed by a compact encoding and a proof that it gives the same answers as the original layers.

See Start How Plotline works

Provenance

The record of where data came from and how it was handled: source versions, hashes, acquisition windows, grid details and read-back checks. It supports replaying an answer; it is not ground truth.

See The data

Receipt

A record attached to an answer that binds it to its inputs and rule: layer versions, grid, geometry digest, rule and hashes. Self-hashes are integrity checks, not signatures.

See How Plotline works Pitch

Registered plot

A plot whose identity and selected cells were stored in advance, like a saved delivery address. EUDR plots are registered once and re-checked whenever a layer updates. A new or changed boundary cannot use this path.

See The speed story Start: the numbers

Registry (registered-plot index)

The stored list of each registered plot's selected cell addresses, bound to a geometry hash and grid identity. It still reads current cell values, so it answers after a layer update. About 44× faster hot.

See The speed story

Screening layer

The broader reduced raster that answers Q1 to Q3: it also keeps post-2020 Hansen loss on all land, for the supplier's own check. 38,513 bytes, 93.8% smaller than the originals.

See How Plotline works

SHA-256 (hash)

A long, reproducible fingerprint of a file or shape. A changed fingerprint means a changed input. To catch deliberate edits you need a trusted, pinned hash, not just one computed from the same file.

See How Plotline works

Sparse loss events

Storing only the rare cells that have post-2020 loss (as gaps plus year symbols) instead of a value at every position, like listing only the days it rained.

See How Plotline works

Standard GeoTIFF control

A plain GeoTIFF of the decision codes, already 98.6% smaller (8,532 bytes). It shows most of the saving comes from knowing what to keep. Our encoding adds the last 28%.

See How Plotline works Pitch

zstd (Zstandard)

A fast lossless compressor. Our lossless v1 store uses it at level 19 on separate bands; a zstd-19 recompression of the whole-tile originals is the yardstick the decision layer is 94.5% smaller than.

See How Plotline works

Performance · 23 terms

Performance

How speed is measured, and the names of the paths we measured.

Baseline (the retained v1 path)

The original-layers query we kept from the start. Every speed multiple in this pack is measured against it, re-measured in each run. Other EUDR tools publish no per-plot latency, so we make no 'faster than' claim about them.

See The speed story

Batch evaluator

A path that answers many new polygons in one vectorised pass. It needs a batch in hand: about 16× on 500 synthetic polygons, but only 1.2× ahead of one-at-a-time on the 17 plots.

See The speed story

End-to-end time

Everything from starting a fresh Python process to the answer, including interpreter start-up and imports. It is mostly start-up, so it barely moves, except for the numpy-free re-check (50.0 ms to 24.9 ms).

See The speed story Start: small print

Fast selection (exact scanline)

The way a new polygon's cells are found: sweep rows and use the crossings for ordinary cell centres, and ask GEOS exactly only for centres near the boundary. About 5× faster on new boundaries, with identical cells.

See The speed story

Fresh-process load + query

The time to load the store and answer all 17 plots in a new process, after imports and excluding Python start-up. It is not disk-cold: the operating system's cache is not controlled.

See The speed story

GDAL / rasterio

GDAL is the standard geospatial file library; rasterio is its Python front end. The original path uses them to read the GeoTIFFs. The decision paths never import them.

See The speed story

GEOS / Shapely

GEOS is the C geometry engine behind Shapely, the Python library we use to validate polygons and run exact boundary tests. We pin Shapely at 2.1.2.

See The speed story

Hot time

How long a query takes once data is already loaded and decoded, like cooking with ingredients on the bench. All the big multiples are hot times for 17 plots on one region, one laptop and a warm cache.

See The speed story Start: the numbers

Multiple (the × figure)

How many times faster a path is than the baseline for the same job. Never blend registered-plot and new-boundary multiples into one number.

See The speed story

New boundary

A polygon we have not registered, so its cells must be selected fresh. It goes through the decision layer with fast selection: about 5.2× faster, about 16× as a large batch.

See The speed story Start: the numbers

NumPy

Python's array library, used for bands, masks and counting. Importing it costs about 25 ms of a roughly 50 ms fresh process, which is why the numpy-free re-check moves end-to-end time.

See The speed story

Numpy-free re-check

Re-checking registered plots with only the Python standard library, decoding just the registered cells from the packed bit-planes. 83× hot, and the one change that halves end-to-end time. It trusts a pinned store hash rather than hashing the full raster.

See The speed story

P0

The baseline: the retained v1 query over the original Hansen layers. About 84.5 microseconds per plot (1.44 ms for 17 plots) hot.

See The speed story

P4

Decision layer plus exact fast selection, for new boundaries. 0.27 ms for 17 plots, 5.2× the baseline.

See The speed story

P4B

The batch evaluator on the decision layer. About 146,000 synthetic polygons per second (15.8×); it needs a batch in hand.

See The speed story

P5d

The registered-plot index at the decision level, with NumPy. 0.032 ms for 17 plots, 44× the baseline.

See The speed story

P5Ld

The numpy-free registered re-check at the decision level. 0.017 ms for 17 plots, 83× hot; 24.9 ms end-to-end against 50.0 for P5d.

See The speed story

P6d

The registered-plot answer table at the decision level. 0.0035 ms for 17 plots, about 410×, a stored answer rather than a recomputed one.

See The speed story

Path names (P0 to P6d)

Short labels for the measured query paths. P0 original v1; P3 decision store; P4 fast selection for new boundaries; P4B batch; P5 registry; P5L numpy-free registry; P6 answer table. A trailing d means the decision level, s the screening level.

See The speed story

Peak memory (RSS)

The most physical RAM a child process held, including Python and imports. For registered plots it falls from 75 MB (original) to 37 MB, and 23 MB numpy-free.

See The speed story

Scanline

A row-by-row way to find which cells a polygon covers, like sweeping a ruler across graph paper. It can be slower on boundary-heavy 'sawtooth' shapes, where the NumPy scan is used instead.

See The speed story

Speed-up phases (1 to 4)

The sequence of speed work after the decision layers were built on the afternoon of 15 Oct: Phase 1 (evening), Phase 2 (night), Phase 3 (late night), Phase 4 (16 Oct early morning). Registered plots went 24× to 44×; new boundaries 2.2× to 5.2×. No output, byte or format changed.

See The speed story

Whole tile

A full 10° × 10° source tile, about 1.6 billion cells. We measured storage on one (422 MB down to 8.2 MB) but did not run queries at tile scale.

See The speed story Start: the numbers
