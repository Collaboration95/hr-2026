Decision layer: algorithm, schema and benchmarks

Each map cell of the sample region is reduced to one of 20 codes. A 6,146 B store returns the same plot-query outputs as the original layers for all 744,732 cells, under the stated centre rule.

1 · Framing

What went in

EUDR screening intersects farm plots with years of forest maps and repeats the check when a map updates. The decision layer keeps only the facts that check reads.

Problem
Compact multi-layer, multi-year storage and efficient queries that preserve the information needed to reproduce plot-level decisions (printed SystemEarth brief, challenge 06).
Layers
Hansen GFC 2025 v1.13 treecover2000, lossyear, datamask (about 28 m cells) and JRC Global Forest Cover 2020 v4 (about 9 m cells).
Region
Surat Thani, Thailand: 98.772–99.081°E, 8.431–8.582°N. 1,233 × 604 = 744,732 cells, about 34 × 17 km. 17 supplied plots (not shown on this page).
Stack
Python 3.14 engine (numpy, rasterio, shapely) and a React + TypeScript + Vite app. This page is static HTML, JavaScript and three.js, no build step.
AI use
No machine-learning model in the pipeline. AI coding assistants wrote and tested much of the code. A learned codec selector was tried and dropped because it lost to a plain GeoTIFF.

3 · Schema

20 codes, two levels

The screening level keeps every post-2020 loss year. The decision level forgets the loss year on land that was not forest in 2020, so codes 3–7 merge into code 2.

4 · Store file

.plds byte layout

One file holds a 20-byte prefix, a canonical-JSON header and the payload: four bit-planes and a sparse set of loss events. The checks run before any decoded cell is used.

    10 · Limits

    What is and is not proven

    The results are encoding and query evidence on public layers under a written rule. They are mapped observations, not compliance findings.

    Shown
    • Identical plot-query outputs for all 744,732 cells at both levels, and so for every polygon in the region under the centre rule.
    • 17 of 17 supplied plots, 9,829 of 9,829 fuzzed polygons, and 0 mismatches between fast and reference selection on 4,920 validator-generated geometries.
    • One flipped cell, a moved vertex and a flipped JRC bit are each detected.
    • Storage on one region (99.0% smaller) and on a whole tile (98.0% smaller, storage only).
    • Per-plot cost once the layer is local, on one laptop with a warm cache.
    Not shown
    • That the rule matches SystemEarth's own reading of the EUDR definitions; it has not been approved.
    • The 0.5 ha minimum area, the "able to reach 5 m in situ" test, protected areas (WDPA licence unclear) and legality layers.
    • Queries at tile scale, a multi-region workload, or any "faster than other tools" claim: no other EUDR tool publishes per-plot latency.
    • That JRC sampling at the Hansen centre is neutral in general. No plot decision changes under majority or any-forest rules, but only 1 of 17 plots has forest.
    • Anything about supplier intent. Counts are cells, not hectares.
    • Speed for a single new plot from the batch evaluator, or for plots not registered in advance on the index and table paths.
